Exemple pratique DDD avec MongoDB (Node.js)
Ce  document  montre  un  exemple  concret  Domain-Driven  Design  (DDD) appliqué  à  une  petite
application de gestion de tâches (Task Management). L'objectif : illustrer les concepts de base (Bounded
Context, Entités, Value Objects, Agrégats, Repositories, Domain Services, Domain Events) et fournir un
squelette de projet Node.js qui utilise MongoDB comme infrastructure de persistance.
Contexte métier
Application : TaskFlow — gérer des tâches pour une équipe. Fonctions principales : créer des tâches,
attribuer une tâche, changer le statut, ajouter des commentaires, prioriser .
Bounded Contexts : - User Context : création / gestion des utilisateurs - Task Context : tout le domaine
des tâches (agrégat Task)
Ubiquitous Language : Task, User , Assignee, Status, Priority, Comment, Aggregate Root, Repository.

8) Transactions et consistance
Utiliser les transactions MongoDB (sessions) pour des cas multi-documents (ex : transfert de
propriété, opérations financières). Dans cet exemple simple, chaque tâche est mono-document.
Si vous avez des invariants couvrant plusieurs collections, encapsulez-les via application service
et utilisez session.startTransaction() dans l'infra.

11) Bonnes pratiques DDD appliquées
Séparer clairement Domain / Application / Infra / Interfaces
Modéliser les invariants dans les agrégats
Repository retourne des agrégats, cache la persistance
EventBus découple effets secondaires
Keep it modular : chaque Bounded Context dans un package/repo séparé si nécessaire
12) Extensions possibles
CQRS : séparer writes (command handlers) des reads (projections + query handlers)
Event sourcing : stocker uniquement les events et reconstruire l'agrégat
Utiliser TypeScript pour types forts
Ajouter validation (class-validator), logging, monitoring
